# Feature List: บันทึก Log และการปฏิบัติตาม PDPA เบื้องต้น (Logging & Basic PDPA Compliance)

> สร้างเมื่อ 2026-08-15
> อ้างอิงจาก [[../01-spec/20260802-03-logging-pdpa-compliance|บันทึก Log และการปฏิบัติตาม PDPA เบื้องต้น (Logging & Basic PDPA Compliance)]]

## รายการฟีเจอร์

| # | ฟีเจอร์ | คำอธิบาย | Priority | อ้างอิง User Story |
|---|---|---|---|---|
| 1 | Order/transaction log | บันทึกทุกออเดอร์พร้อม timestamp, หมายเลขโต๊ะ, รายการสินค้า, และการเปลี่ยนสถานะออเดอร์ | Must | ในฐานะเจ้าของร้าน ฉันต้องการให้ระบบเก็บ log ออเดอร์และการเข้าถึง dashboard เพื่อใช้ตรวจสอบย้อนหลังเมื่อเกิดปัญหาหรือข้อพิพาท |
| 2 | Access log | บันทึกการเข้าถึงหน้า sales dashboard (เวลาที่เข้าถึง, IP address) เพื่อเตรียมพร้อมสำหรับระบบ login/สิทธิ์การเข้าถึงในอนาคต | Must | ในฐานะเจ้าของร้าน ฉันต้องการให้ระบบเก็บ log ออเดอร์และการเข้าถึง dashboard เพื่อใช้ตรวจสอบย้อนหลังเมื่อเกิดปัญหาหรือข้อพิพาท |
| 3 | Error/system log | บันทึกข้อผิดพลาดของระบบ เพื่อใช้ debug และตรวจจับความผิดปกติ | Must | ในฐานะเจ้าของร้าน ฉันต้องการให้ระบบเก็บ log ออเดอร์และการเข้าถึง dashboard เพื่อใช้ตรวจสอบย้อนหลังเมื่อเกิดปัญหาหรือข้อพิพาท |
| 4 | นโยบายเก็บรักษา log 90 วัน | เก็บ log ทั้งสามประเภท (order/transaction, access, error) ไว้ 90 วัน แล้วลบทิ้ง/anonymize อัตโนมัติหลังพ้นกำหนด | Must | Business Rule: Log ทุกประเภทเก็บไว้ 90 วัน แล้วลบทิ้งอัตโนมัติ |
| 5 | Privacy notice แบบข้อความแจ้งเตือนเฉยๆ บนหน้าสั่งอาหาร QR | แสดงข้อความสั้นๆ บนหน้าสั่งอาหาร QR แจ้งลูกค้าว่าระบบมีการเก็บ log การใช้งาน (เช่น เวลาที่สั่ง, IP address) เพื่อวัตถุประสงค์ด้านการดำเนินงานและความปลอดภัย เป็น implicit notice ไม่ใช่ explicit consent (ไม่มีปุ่ม/checkbox ให้กด) | Must | ในฐานะเจ้าของร้าน ฉันต้องการให้ระบบแจ้งลูกค้าแบบง่ายๆ ว่ามีการเก็บ log การใช้งาน เพื่อให้ร้านปฏิบัติตาม PDPA ในระดับพื้นฐาน โดยไม่ต้องสร้างระบบ consent management ที่ซับซ้อน |

## หมายเหตุ

- ฟีเจอร์ทั้งหมดในรายการนี้เป็น Must เนื่องจากเป็นข้อกำหนดพื้นฐานด้าน compliance ที่ spec ต้นทางระบุว่าต้องการ "เท่าที่จำเป็น" เท่านั้น จึงไม่มีการแบ่งชั้นความสำคัญรอง (Should/Could/Won't)
- Log ที่มีข้อมูลซึ่งอาจนับเป็นข้อมูลส่วนบุคคลทางอ้อม (เช่น IP address ใน access log) ต้องจำกัดการเข้าถึงเฉพาะเจ้าของร้าน/ผู้ดูแลระบบเท่านั้น ตาม business rule ของ spec ต้นทาง
- Privacy notice (#5) ไม่ต้องมีกลไกให้ลูกค้ากดยอมรับ และไม่ต้องบันทึกสถานะการยอมรับ (consent record) ในระบบ
- ระบบจัดการ consent แบบเต็มรูปแบบ (checkbox/บันทึกสถานะยอมรับ), ช่องทางขอเข้าถึง/แก้ไข/ลบข้อมูลส่วนบุคคล (data subject rights portal), กระบวนการแจ้งเหตุข้อมูลรั่วไหลอัตโนมัติ (breach notification automation), และตำแหน่ง DPO เต็มรูปแบบ อยู่นอกขอบเขต (out of scope) ตาม spec ต้นทาง จึงไม่ปรากฏในรายการนี้
- (ข้อสันนิษฐาน) spec ต้นทางยังไม่ได้ระบุ UI/เครื่องมือให้เจ้าของร้านค้นหา/ดู log ย้อนหลังโดยเฉพาะ รายการฟีเจอร์นี้จึงตีความว่าการเก็บ log (#1-#3) หมายถึงการบันทึกข้อมูลลงระบบจัดเก็บเท่านั้น ส่วนวิธีที่เจ้าของร้านจะเข้าถึง/ค้นดู log จริงยังไม่ได้กำหนดไว้ (ดู pain point ที่เกี่ยวข้องใน user journey)
