# บันทึก Log และการปฏิบัติตาม PDPA เบื้องต้น (Logging & Basic PDPA Compliance)

> สร้างเมื่อ 2026-08-02

## บริบท / ที่มา

ระบบสั่งกาแฟผ่าน QR code จากโต๊ะ (ดู [[20260802-01-cafe-table-self-order|ระบบสั่งกาแฟจากโต๊ะ]]) และ [[20260802-02-sales-dashboard|หน้า Dashboard ดูยอดขาย]] เก็บข้อมูลออเดอร์เข้าระบบอยู่แล้ว แต่ยังไม่มีนโยบายเรื่อง logging ที่ชัดเจน และยังไม่ได้พิจารณาข้อกำหนดตาม PDPA (พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล) เจ้าของร้านต้องการเพิ่มเรื่องนี้เข้าไปเพื่อให้ตรวจสอบย้อนหลังได้และปฏิบัติตามกฎหมายในระดับพื้นฐาน โดยยืนยันชัดเจนว่าต้องการทำ "เท่าที่จำเป็น" เท่านั้น ไม่ต้องการระบบที่ซับซ้อน เนื่องจากระบบปัจจุบันยังไม่เก็บข้อมูลระบุตัวตนลูกค้าโดยตรง (ไม่มีชื่อ/เบอร์โทร/บัญชีสมาชิก) และ sales dashboard ยังไม่มีระบบ login

## Feature Requirements

- **Order/transaction log**: บันทึกทุกออเดอร์ที่เข้าระบบ พร้อม timestamp, หมายเลขโต๊ะ, รายการสินค้า, และการเปลี่ยนสถานะออเดอร์
- **Access log**: บันทึกการเข้าถึงหน้า sales dashboard (เวลาที่เข้าถึง, IP address ของผู้เข้าถึง) เพื่อเตรียมพร้อมสำหรับเมื่อมีการเพิ่มระบบ login/สิทธิ์การเข้าถึงในอนาคต
- **Error/system log**: บันทึกข้อผิดพลาดของระบบ เพื่อใช้ debug และตรวจจับความผิดปกติ
- **นโยบายเก็บรักษา log**: เก็บ log ทั้งสามประเภท (order/transaction, access, error) ไว้ 90 วัน แล้วลบทิ้ง/anonymize อัตโนมัติหลังพ้นกำหนด
- **ข้อความแจ้งเตือนความเป็นส่วนตัว (privacy notice) แบบง่าย**: แสดงข้อความสั้นๆ บนหน้าสั่งอาหาร QR แจ้งลูกค้าว่าระบบมีการเก็บ log การใช้งาน (เช่น เวลาที่สั่ง, IP address) เพื่อวัตถุประสงค์ด้านการดำเนินงานและความปลอดภัย เป็นข้อความแจ้งเตือนเฉยๆ ไม่ต้องมีปุ่ม/checkbox ให้ลูกค้ากดยอมรับ (implicit notice ไม่ใช่ explicit consent)

## User Stories / Use Cases

- ในฐานะเจ้าของร้าน ฉันต้องการให้ระบบเก็บ log ออเดอร์และการเข้าถึง dashboard เพื่อใช้ตรวจสอบย้อนหลังเมื่อเกิดปัญหาหรือข้อพิพาท
- ในฐานะเจ้าของร้าน ฉันต้องการให้ระบบแจ้งลูกค้าแบบง่ายๆ ว่ามีการเก็บ log การใช้งาน เพื่อให้ร้านปฏิบัติตาม PDPA ในระดับพื้นฐาน โดยไม่ต้องสร้างระบบ consent management ที่ซับซ้อน

## Business Rules

- Log ทุกประเภท (order/transaction, access, error) เก็บไว้ 90 วัน แล้วลบทิ้งอัตโนมัติ
- Log ที่มีข้อมูลซึ่งอาจนับเป็นข้อมูลส่วนบุคคลทางอ้อม (เช่น IP address ใน access log) ต้องจำกัดการเข้าถึงเฉพาะเจ้าของร้าน/ผู้ดูแลระบบเท่านั้น
- Privacy notice บนหน้าสั่งอาหาร QR เป็นข้อความแจ้งเตือนเฉยๆ (implicit notice) ไม่ต้องมีกลไกให้ลูกค้ากดยอมรับ และไม่ต้องบันทึกสถานะการยอมรับ (consent record) ในระบบ
- เนื่องจากระบบไม่เก็บข้อมูลระบุตัวตนลูกค้าโดยตรง (ไม่มีชื่อ/เบอร์โทร) เวอร์ชันนี้จึงตั้งใจไม่ทำ: ระบบจัดการ consent แบบเต็มรูปแบบ (checkbox/บันทึกสถานะยอมรับ), ช่องทางขอเข้าถึง/แก้ไข/ลบข้อมูลส่วนบุคคล (data subject rights portal), กระบวนการแจ้งเหตุข้อมูลรั่วไหลอัตโนมัติ (breach notification automation), หรือตำแหน่ง DPO เต็มรูปแบบ — ให้พิจารณาเพิ่มเติมในอนาคตหากมีฟีเจอร์ที่เก็บข้อมูลระบุตัวตนลูกค้าโดยตรง (เช่น ระบบสมาชิก/แต้มสะสม)

## ขอบเขต (Scope)

- In scope: order/transaction log, access log สำหรับ sales dashboard, error/system log, นโยบาย retention 90 วันสำหรับ log ทั้งหมด, privacy notice แบบข้อความแจ้งเตือนเฉยๆ บนหน้าสั่งอาหาร QR
- Out of scope: consent management system ที่ซับซ้อน (checkbox/ปุ่มยอมรับ, การบันทึกสถานะ consent), data subject rights portal (ช่องทางขอเข้าถึง/แก้ไข/ลบข้อมูลส่วนบุคคลแบบเป็นทางการ), breach notification automation, ตำแหน่ง DPO เต็มรูปแบบ, การเก็บ log แยกตามสาขา (ร้านมีสาขาเดียว)
